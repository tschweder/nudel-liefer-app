## Local database

```bash
cp .env.example .env
docker compose up -d          # postgres:16 + minio
pnpm db:migrate && pnpm db:seed
pnpm test                     # includes the DB integration test when DATABASE_URL is set
```

Without Docker: `pnpm db:embedded` starts a throwaway PostgreSQL (npm `embedded-postgres`) on port 5432 and prints the `DATABASE_URL`; leave it running in a second terminal.

## Object storage (uploads)

Uploads go browser -> presigned `PUT` -> bucket (the app server never proxies the bytes). The bucket stays **private**; images are shown through signed `GET` URLs valid for 1 hour (`Storage.getReadUrl`).

- Local: `docker compose up -d` starts MinIO (API on http://localhost:9123, console on http://localhost:9121, `minioadmin`/`minioadmin`) and creates the bucket `nudel-photos`. MinIO allows cross-origin `PUT` from the dev server by default.
- Cloudflare R2: create the bucket in the EU jurisdiction and an API token with object read/write. The bucket needs a **CORS rule** so the browser may `PUT` from the app origin: allowed origins = the app URL(s), methods `GET, PUT`, allowed headers `content-type, content-length`, max age 3600.
- Keys are generated by the server: `customers/<uuid>.<ext>` and `screenshots/<uuid>.<ext>`.

## Hosted environments (Vercel)

Set in Vercel, never in git. Production values, preview values and local values must all differ (especially `AUTH_SECRET`). The complete click-by-click setup, including which variable goes to which Vercel environment, is in [`deploy.md`](./deploy.md). The build (`pnpm build:vercel`) fails early with a readable list when a required variable is missing or still points to localhost (`scripts/check-deploy-env.ts`).

Variables Vercel provides automatically and the app reads only for `GET /api/health`: `VERCEL_ENV`, `VERCEL_GIT_COMMIT_SHA`, `VERCEL_REGION`.

## Demo data (NUD-060)

`pnpm db:seed --demo` adds the demo depot, 20 customers with generated photos, 2 extra products (8 in total) and confirmed orders for the next delivery day (see `docs/demo.md`). It needs `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` (and `S3_ENDPOINT` for MinIO) because the photos are stored in the object storage; `pnpm db:seed --demo --no-photos` skips the photos and needs no S3. No new environment variables. Never run it against production.

## Translation retry job (NUD-070)

`localize()` never blocks saving: when DeepL is down the text is stored with its source locale only and `meta.pendingTranslation = true` inside the `LocalizedText` JSON (no extra column or table). `vercel.json` registers a cron job that calls `GET /api/cron/retry-translations` every 10 minutes; it looks for pending texts in every column listed in `src/server/translation-pending.ts` (`Customer.notes`, `Stop.problemNote`), fills the missing locales (never overwriting an existing one) and clears the flag. A provider error ends the run, the next run tries again. Vercel Hobby projects only allow daily cron jobs; the 10 minute schedule needs the Pro plan (the budget in D4 includes it) — on Hobby, change the schedule in `vercel.json` or call the route from another scheduler with the same bearer header. Manual run: `curl -H "Authorization: Bearer $CRON_SECRET" https://<app>/api/cron/retry-translations` (answers with counts per column).
