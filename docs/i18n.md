# UI texts and the native-speaker review

The app has four UI locales: `de`, `zh-Hans`, `zh-Hant-HK`, `zh-Hant-TW` (backlog D14/D15).
This page explains which message files are edited by hand, and how a native speaker reviews the
Chinese texts without touching any code.

## Message files

| File | Kind | Who edits it |
|---|---|---|
| `messages/de.json` | hand-edited | developers (source of meaning) |
| `messages/zh-Hans.json` | hand-edited | developers, and the Simplified-Chinese reviewer (via CSV import) |
| `messages/overrides/zh-Hant-HK.json` | hand-edited, usually small | Hong Kong reviewer (via CSV import) |
| `messages/overrides/zh-Hant-TW.json` | hand-edited, usually small | Taiwan reviewer (via CSV import) |
| `messages/zh-Hant-HK.json`, `messages/zh-Hant-TW.json` | **generated, never edit** | `pnpm i18n:build` |

The generated files are `OpenCC(zh-Hans.json)` (HK: `s2hk`, TW: `s2twp` with phrase conversion),
then the matching override file is merged on top. So:

- fixing a Simplified text automatically fixes the Traditional texts that were derived from it;
- a Traditional text that is wrong for one region only gets an entry in that region's override file;
- `pnpm i18n:check` fails when a generated file does not match a fresh build, or a key is
  missing/empty, or an ICU message is invalid.

Commands: `pnpm i18n:build`, `pnpm i18n:check`, `pnpm i18n:export`, `pnpm i18n:import <csv>`.

## Review workflow

### For the developer

1. `pnpm i18n:export` writes `./i18n-review.csv` (UTF-8 with BOM, comma separated, one row per
   key). Use `--out <file>` for another path, `--delimiter ";"` for a semicolon file.
   The file is gitignored (`/i18n-review*.csv`): **never commit a CSV that contains real review
   output**; send it to the reviewers by mail or shared drive.
2. Send the CSV to the reviewers, together with the route list below and the logins for a test
   deployment (or the demo seed, see `docs/demo.md`).
3. Take the returned CSV(s) and run `pnpm i18n:import returned.csv --dry-run` to see which
   files and keys would change, then `pnpm i18n:import returned.csv`. The import regenerates the
   Hant files. Then run `pnpm i18n:check` and commit the changed JSON files
   (`zh-Hans.json`, `overrides/*`, `zh-Hant-*.json`).
   Several reviewers: import their files one after the other (each import is all-or-nothing).
4. Reviewer comments (column `reviewer_comment`) are not stored anywhere. Keep the CSV, or copy
   the relevant comments into the ticket.

Import rules (nothing is written when any rule is violated):

- A row with an unknown `key`, a duplicate `key`, or an empty `key` is refused.
- A correction must be valid ICU message syntax and use exactly the same placeholders as the
  German text (`{count}`, `{name}`, `<b>…</b>`, …); see "Placeholders" below.
- If the text in the CSV differs from the current text in the repository (someone edited the
  message after the export), the row is refused; re-export, or use `--force` knowingly.
- An empty `corrected_*` cell means "no change". A correction equal to the current text changes
  nothing. Leading/trailing spaces of a correction are removed.
- `corrected_zh-Hans` is written into `zh-Hans.json`. `corrected_zh-Hant-HK` / `-TW` is written
  into the matching override file, unless it is identical to what OpenCC produces (then no
  override is needed, and an existing override for that key is removed).
- German is not corrected via the CSV; report German problems in `reviewer_comment`.

### For the reviewers (Simplified Chinese; Traditional Chinese for HK and/or TW)

Columns of the CSV:

| Column | Meaning |
|---|---|
| `key` | technical id, never change it |
| `de` | the German source text (for meaning) |
| `zh-Hans` | current Simplified text |
| `zh-Hant-HK` | current Traditional (Hong Kong) text, **generated** |
| `zh-Hant-TW` | current Traditional (Taiwan) text, **generated** |
| `route_hint` | where to see the text in the app (see below) |
| `reviewer_comment` | free text: anything unclear, doubts, German problems |
| `corrected_zh-Hans` | **fill in only when the Simplified text should change** |
| `corrected_zh-Hant-HK` | fill in only when the HK text should change |
| `corrected_zh-Hant-TW` | fill in only when the TW text should change |

Only the last four columns (comment and three corrections) are for you; do not edit the other
columns. Leave a `corrected_*` cell empty when the text is fine. Write the **complete** new text,
not a fragment.

How to treat the generated Traditional texts:

- The Simplified reviewer reviews `zh-Hans` only. Whatever is fixed there flows into HK and TW.
- The Traditional reviewer reads the `zh-Hant-HK` / `zh-Hant-TW` columns as a native reader
  would see them in the app. The text was produced by a machine conversion from Simplified, so
  expect wording that is correct in characters but not natural in the region (e.g. mainland
  vocabulary). Correct it only in the region's own `corrected_` column (HK and TW may differ).
  If the same Traditional wording is wrong in both regions because the Simplified source is poor,
  prefer a comment to the Simplified reviewer, or correct `zh-Hans` yourself if you read it too.
- Written standard Chinese only, no Cantonese colloquialisms (D14), also for HK.
- Customer names and addresses are never translated, they do not appear in this file.

Opening the file: Excel on a German system expects `;` instead of `,`. Either use
*Data > From Text/CSV* (UTF-8) or open it in LibreOffice / Google Sheets. Save it as CSV (UTF-8)
again; a `;`-separated file is accepted by the import, as is one without the BOM. Do not let the
spreadsheet reformat cells (no auto-correct of quotes into typographic quotes in the ICU parts).

Placeholders: curly braces are variables or plural rules and must stay as they are:
`{count, plural, =0 {没有条目} other {# 个条目}}`. Translate only the text inside the inner braces
`{…}` of the plural branches, never `count`, `plural`, `other`, `one`, `#`. Check the `de` column to
see which placeholders a text needs; the import tells you when one is missing or added.

### Where to see a text (route hints)

`route_hint` gives the page without the locale. Prepend the locale segment, e.g.
`/admin/orders/new` is `https://<host>/zh-Hant-HK/admin/orders/new`. `[id]` / `[stopId]` stand for
any real record. Text in parentheses is a description, not a URL (shared buttons, error pages).
Driver screens (`/driver…`) are meant for a phone: use a narrow browser window.

The mapping from key prefix to route lives in `scripts/lib/i18n-routes.ts` (longest prefix wins).
When a ticket adds a new key namespace, add one line there; `pnpm i18n:export` warns about keys
without a hint, and a unit test fails when an entry matches no key any more.

## Glossary of fixed terms

Use these words consistently (backlog section 3). German is the source of meaning; the Chinese
column shows the term the current texts use, so the reviewer can confirm or replace it (change a
term everywhere, not in one place only, and report such a decision in `reviewer_comment`).

| Concept (code) | German UI | Notes |
|---|---|---|
| `Tour` | Tour | One driver's delivery run on one date. Do not call it "Route"; "route" is only the road path. |
| `Stop` | Stopp | One visit to one customer in a tour. All confirmed orders of a customer for that date are merged into one stop. |
| `Order` | Bestellung | What one customer ordered for one delivery date. |
| `OrderItem` | Bestellposition | Product and quantity inside an order. |
| `Customer` | Kunde | A business with exactly one delivery address and one confirmed pin. |
| `Product` | Nudelsorte / Produkt | A pasta article with a unit. |
| `Depot` | Fabrik / Depot | Start and end point of every tour. |
| `Release` | Freigabe | Making a tour visible to the driver. |
| `Pin` | Kartenpunkt | The confirmed position of a customer on the map. |
| unit `PACK` etc. | Einheit | A product's unit of measure (`KG`, `PACK`, `CRATE`, `PIECE`). **"Einheit" is the measure unit of a product; it is not a time period ("Stunde" is time).** |

The exact Chinese terms for these concepts are a reviewer decision; until the review is done
they are agent-written and **unreviewed**.

## Status of the Chinese texts

All current Chinese UI texts (`zh-Hans`, and therefore the generated HK/TW texts) were written by
the development agent and have **not** been checked by a native speaker. Do not go live with the
driver app in Chinese before the review in this document was done and imported.
